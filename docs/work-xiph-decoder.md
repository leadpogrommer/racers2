# Ogg/Vorbis decoder identification and reuse

The commentary reader at `0x004f2740` uses the exact Ogg/Vorbis header sequence: synchronization state, page serial number, logical stream initialization, Vorbis info/comment initialization, three header packets, synthesis and block initialization. The decode loop at `0x004f29f0` extracts packets, calls synthesis/blockin/pcmout/read, interleaves signed 16-bit samples and clips to [-32768,32767]. This is the interface sequence documented by [Xiph](https://xiph.org/vorbis/doc/programming.html).

Official libogg/libvorbis 1.0rc2 archives were downloaded and compiled with the pinned VC6 SP5 compiler, `/O2 /Ob1 /MT /Z7`. A scan over 4,397 discovered retail functions against 266 COFF functions found 94 relocation-masked candidates. These are saved with portable member names in [the candidate inventory](../reccmp/xiph-library-candidates.csv). They are evidence candidates, not blanket LIBRARY annotations or game-function matches. Among them, `vorbis_synthesis_blockin` has 943 unmasked identical bytes, and `vorbis_info_clear` has 320. `vorbis_synthesis_pcmout` and `vorbis_synthesis_read` are fully byte-identical at this stage. Source/caller review identifies 25 public decoder interfaces in `library_xiph.h`; internal candidates remain unannotated. Original addresses remain excluded from game-function totals.

The actual x86 structures match the commentary object's observed offsets: sync +0x2028, stream +0x2048, page +0x21b0, packet +0x21c0, info +0x21e0, comment +0x2200, DSP +0x2210, block +0x2280, input pointer +0x22f0 and PCM scratch +0x22f4. Compile-time assertions validate these offsets and the whole 0x42f8 object. The selected release supplies compatible implementation source; the exact retail release/revision is not established. Ogg CRC initialization inlining and several internal decoder bodies differ. Archive URLs and hashes are pinned in [third-party source notes](../3rdparty/README.md); upstream BSD notices are retained.

The game wrapper preserves its DirectSound interfaces, callback stack cleanup, circular queue, forward DWORD/tail copies and x87 rounding. In particular, float sample *32767 is spilled to double before FISTP under the current FPU rounding mode. It is not replaced with a truncating C++ integer conversion. The first read helper ignores its offset argument, uses the handle's current position, and reads through a 32-entry request table before copying to a caller destination. Its internal staging-buffer ownership is still unresolved: retail BSS starts with null pointers and no initialization was found in the currently recovered callers. This path remains STUB and has not been executed.

The service PCM append path also has an unresolved extent: the original 0x2a624-byte service ends after a 0x5a00-byte staging tail, while the append threshold uses 0x15888 bytes. The recovered code retains the observed addressing and stays STUB; no safe-runtime claim is made for that branch.

No game, decoder asset probe or audio playback was run for this work.

The instruction matcher associates one original address with one rebuilt address. The linker folds the stream's +0x14 getter with the renderer texture-offset getter, and folds upstream bare-RET callbacks with existing empty destructors. `reccmp/folded-functions.csv` records the exact symbols and complete, relocation-free function bytes for these cases. Before accepting an alias, `tools/folded_functions.py` checks the pinned original hash, both PE address mappings, the function size inventory, the literal original bytes and the rebuilt bytes at the actual linker-map symbol. It adds the independently verified alias to JSON/HTML/SVG reports and keeps the normal match guard active. Compiler/linker optimizations remain unchanged. No artificial instruction or global write is introduced.

Four additional wrapper methods measure exactly in both builds: stream destruction, playback-buffer release, waiting for a read request and indexing a read request. The completed-read poller deliberately compares `GetLastError()` with retail `ERROR_IO_PENDING` (997), including that unusual behavior; replacing it with `ERROR_IO_INCOMPLETE` (996) would change the original branch.

`FindCompletedAudioRead` measures 97.96% in both builders after restoring error 997. It is implemented as a reviewed equivalent near match: the only remaining instruction difference is reccmp labeling the array-end comparison through adjacent rebuilt CRC storage. The retail address `0x006e4e20` equals the first request byte-count address `0x006e4820 + 32*0x30`; the rebuilt comparison uses the same 32-entry extent. All API calls, conditionals, error writes, active-slot release and output-index writes otherwise match. This is data-address normalization, with no unresolved control-flow difference.
